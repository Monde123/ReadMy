# ReadMy — Visual Diversity

## Objective

ReadMy aims to provide a broad collection of GitHub profile README architectures, not a set of near-duplicate text variants.

A visual architecture defines the structure and graphic logic of a README: layout, alignment, density, section rhythm, project format, skill layout, image strategy, and navigation model.

## Rule of uniqueness

Each complete visual architecture may be used only once in the repository.

A template is considered a duplicate when it keeps the same:

- overall layout,
- section arrangement,
- project presentation,
- content density,
- navigation pattern,
- visual rhythm,
- type of skill mapping,
- image strategy,
- palette and composition logic.

A new template may reuse small components, but not a whole design system.

## Diversity strategy

ReadMy will continue to expand by designing new visual systems, not by changing the wording of existing ones.

## Design checklist for every future template

Before adding a template, verify that it introduces a new visual combination with at least one meaningful difference in:

1. page composition
2. section order
3. project format
4. skill format
5. navigation system
6. density and rhythm
7. content framing
8. visual language
9. image strategy
10. overall reading experience

## Why this matters

Without this rule, a repository of README files becomes a pile of variations on the same layout. ReadMy should instead feel like a curated gallery of design systems for personal technical identity.

The project must be recognized as a design resource, not only as a collection of Markdown snippets.
