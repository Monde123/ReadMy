# ReadMy — Design Principles

## 1. Make the profile understandable quickly

The first screen should communicate who the person is, what they build, and which direction they are pursuing.

## 2. Present a coherent identity

A profile should not be a random inventory of tools. Skills, projects, and goals should support the same professional narrative.

## 3. Show evidence

A project description should explain the problem, the contribution, and the technology. A long badge wall is not a substitute for evidence.

## 4. Use progressive disclosure

Place the most important information first. Move detailed certifications, statistics, and extended learning lists lower in the document.

## 5. Prefer semantic Markdown

Use headings, lists, tables, and links for meaning. HTML and images are welcome for layout, but the profile should remain readable as plain Markdown.

## 6. Keep decoration purposeful

Banners, animations, graphs, and badges should reinforce identity or navigation. Remove them when they compete with the content.

## 7. Keep examples honest

Fictional profiles may be polished, but they should not make unverifiable claims such as invented employment, awards, or production impact.

## 8. Design for customization

A user should be able to identify what to change without reverse-engineering the template.
